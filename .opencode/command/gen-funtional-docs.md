# Task description

Your task is to analyze the source code of a given repository and generate a high-level functional documentation package.

This documentation must be understandable by non-technical stakeholders, such as product owners, business analysts, and clients. They are familiar with the product's business logic and functional definitions, but do not understand code or technical jargon.

Generate a group of documentation files in markdown, inside de docs-functional folder.

Look for the code to be documented in the folders code.

## The documentation should include:

- A clear overview of the system and its purpose.
- Key features and functionalities described in plain language.
- A breakdown of main modules or components and what each one does from a user/business perspective.
- Descriptions of key workflows or user journeys.
- Any external dependencies, integrations, or APIs explained in non-technical terms.
- (Optional) Diagrams or visual aids that help communicate how the system works functionally.
- Avoid implementation details, architecture-specific terms, or low-level code explanations unless absolutely necessary—and always explain them in layman's terms.

## Instructions to organize the documentation files:

- Create a Index.md file
  - This file needs a navigation index of all the documentation.
- Each file needs a proper index
- Separate the documentation in logic folders
